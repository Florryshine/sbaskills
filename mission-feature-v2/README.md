# Mission Feature — v2 (corrected)

This replaces the earlier `mission-feature.zip`, which was built against
wrong table names. **Don't use the old zip — use this one.**

## What changed and why

The World Map (`app/syllabus/page.js`) actually links by `game_topics.id`,
not a `knowledge_assets.id`. Reading the real file (you pasted it) showed:

- `game_topics` is a published, student-safe projection of a
  `knowledge_asset`, created by `app/api/admin/games/publish/route.js`.
- `student_topic_progress` is keyed by `game_topic_id`, not
  `knowledge_asset_id`.
- Quizzes have **two separate systems**: manually-authored ones in
  `quizzes` (played at `/quiz/[id]`, already gamified), and
  content-engine ones in `quiz_drafts` (played at
  `/quizzes/[id]?draft=true`, which **awarded no XP and saved nothing**
  until the patch included here).
- Boss battles generated by the content engine (`boss_battle_drafts`) get
  copied into the live `boss_battles` table on publish — that part was
  already fully gamified, just needed the right id resolved.
- Flashcards were correct in the original build — no change there.

Full details are in the comments at the top of `lib/journeyEngine.js` and
`components/mission/MissionRunner.js`.

## Install steps

1. **Delete the old `/mission` and `/api/mission` folders** if you already
   copied the v1 zip in — they used the wrong `[assetId]` param name.

2. Copy the folders in, matching your repo's existing structure:
   ```
   app/api/mission/[gameTopicId]/  → your app/api/mission/
   app/mission/[gameTopicId]/      → your app/mission/
   components/mission/             → your components/mission/
   lib/journeyEngine.js            → your lib/
   supabase/migrations/...sql      → your supabase/migrations/
   ```

3. **Replace** `app/quizzes/[id]/page.js` with `patches/quizzes-id-page.js`
   in this zip. This is a required fix, not optional — without it,
   content-engine quizzes still won't persist or award XP, and the
   Mission's quiz step can never be detected as complete.

4. Apply the migration to Supabase (SQL editor or `supabase db push`).

5. One-line change in `app/syllabus/page.js`, the `Link` inside the map:
   ```js
   <Link href={`/games/${topic.id}`}>{content}</Link>
   ```
   becomes
   ```js
   <Link href={`/mission/${topic.id}`}>{content}</Link>
   ```

## Before you deploy to production — please verify

These are things I could not confirm from code alone and should be
checked against your live Supabase schema:

1. **`student_topic_progress` unique constraint** — the upsert in
   `recordMissionResult()` assumes a unique constraint on
   `(student_id, game_topic_id)`. If the real constraint has a different
   name or columns, the upsert will fail or silently insert duplicates.
2. **`quiz_attempts.quiz_id` — is there a foreign key to `quizzes(id)`?**
   The patch now inserts a `quiz_drafts` id into that column. If there's a
   strict FK constraint pointing only at `quizzes`, that insert will
   error. If so, either drop/loosen the FK or add a `quiz_source` column
   to disambiguate.
3. **`study_note_drafts`, `video_scripts`, `podcast_episodes`** — these
   three activity types were not re-verified this round the way
   quiz/boss/flashcards were. Confirm their student-facing routes and
   publish status columns before trusting the engine's queries against
   them.
4. **Boss battle deep-linking** — `/boss` still has no way to open one
   specific boss battle. The Mission Runner sends the student to `/boss`
   generally; they'll need to find the right one themselves until that
   page gains a `?bossId=` preselect.
