# SBA Whiteboard Animation 2 (experimental)

A separate, isolated Python + FFmpeg renderer. It does not modify or replace
the existing Remotion Video Studio.

## What this first prototype does

- Reads a **scene JSON plan** (never executes AI-generated Python).
- Draws text, lines, polylines, arrows, circles and rectangles progressively.
- Imports local PNG/JPG diagram assets, converts dark artwork into transparent ink, and reveals them progressively.
- Uses seconds from the narration start for every visual element.
- Renders portrait or landscape MP4 with FFmpeg.
- Accepts narration audio generated by the existing Edge TTS workflow.

This is version 0.1: a deterministic drawing prototype, not yet a full
handwriting/illustration system. Text currently reveals left-to-right;
later work can add real pen-stroke fonts, traced SVG paths, imported diagrams,
and automatic word-boundary scheduling.

## Requirements

- Python 3.10+
- FFmpeg installed and available as `ffmpeg` on PATH
- Pillow

## Windows CMD setup

Run each command on one line:

```bat
cd whiteboard_animation_2
py -m venv .venv
.venv\Scripts\activate
py -m pip install -r requirements.txt
ffmpeg -version
```

Put an audio file named `narration.mp3` in
`examples/photosynthesis/`. The included example plan expects a 12-second
audio file; adjust its `duration` and object `start` values to match the
actual narration. Then run:

```bat
py engine.py examples/photosynthesis/scene.json -o photosynthesis-test.mp4
```

## Scene plan format

Every object has a `type`, `start` and `draw_duration`. When an audio file is supplied, the renderer reads its actual duration with `ffprobe`; the optional JSON `duration` is not used to guess the soundtrack length. Coordinates use
the plan's `coordinate_width` (1080 by default), and are scaled to output
width. Supported objects:

- `text`: `text`, `x`, `y`, `size`, optional `bold` and `color`
- `line`: `x1`, `y1`, `x2`, `y2`
- `polyline`: ordered `points` array
- `arrow`: ordered `points` array
- `circle`: `x`, `y`, `radius`
- `rect`: `x`, `y`, `w`, `h`
- `image`: `path`, `x`, `y`, `w`, `h`; local diagram image is converted to ink and revealed from left to right

Colors are RGB arrays. All timing values are seconds from the beginning of
the audio. Keep the audio file and JSON plan together so relative paths work.

## Important

The prototype currently expects narration audio to be supplied; it does not
call TTS itself. The example is a visual/timing scaffold and needs a matching
audio file before it can produce a narrated MP4. No existing SBA routes,
Remotion files, dependencies, or production UI are changed.

## Optional real stroke-tracing backend

The lightweight renderer above is useful for custom timed overlays, but it is
not the strongest handwriting renderer. For clean black-ink illustrations,
there is a second, optional backend: **whiteboard-animator 0.1.1**. It is MIT
licensed, CPU-only, and includes a text detector. Its package is much heavier
(about 77 MB) and has scientific Python dependencies, so it is deliberately
not part of the default requirements. The optional install does not require
the Gemini extra or an API key.

Install it only when you want to test that backend:

```bat
py -m pip install -r requirements-whiteboard-animator.txt
```

Prepare one clean whiteboard-style PNG and one narration WAV per scene. Keep
them beside a manifest based on `examples/animator-manifest.json`, then run:

```bat
py animator_adapter.py examples/animator-manifest.json -o photosynthesis-traced.mp4 --quality high
```

This backend traces finished diagrams and handwriting more naturally than
the simple progressive image wipe in `engine.py`. Its automatic narration
pacing is estimated from image regions, not true word-level speech alignment.
We must judge the actual output before choosing it as the main renderer.
